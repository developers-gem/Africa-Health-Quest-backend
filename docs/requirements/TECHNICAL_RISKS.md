# Technical Risks — audit findings and migration risks

Severity: **Critical** (exploitable now or clinical-safety impact) · **High** · **Medium** · **Low**.
"Status" says whether the already-built API (commit `bbb130c`) addresses it.

## A. Defects and vulnerabilities found in the prototype

| ID   | Severity | Finding                                                                                                                                           | Evidence                                         | Mitigation in target                                                                                                 | Status                               |
| ---- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| R-01 | Critical | Answer keys (`correct`) and feedback for all 38 choices ship in the JS bundle                                                                     | `lib/game-data.ts` imported by client            | Content served via DTOs without keys; correctness/feedback returned only after an answer is submitted; contract test | Planned (Phase 3–4)                  |
| R-02 | Critical | HP, funding, unlocks computed and stored client-side; localStorage edit → 99 999 HP, all tiers                                                    | L11                                              | Server-only rewards via `Attempt`/`Shift`; no client write endpoint for progress                                     | Planned (Phase 4)                    |
| R-03 | Critical | Supabase RLS lets a user upsert any `hp/funding/done` into their own row                                                                          | migration `0000`                                 | Replaced by server-side mutations                                                                                    | Superseded by new API                |
| R-04 | High     | Sign-in merge uses `max(hp)`, `max(funding)` → forged or stale local values enter the account; funding spends undone                              | `index.tsx` `load()`                             | Server is source of truth; guest upgrade in place (D3)                                                               | Identity ✅, progress planned        |
| R-05 | High     | After merge, every save is a full-state upsert → a stale second device overwrites newer progress (data loss)                                      | `index.tsx` `update()`                           | Atomic `$inc` on server events; clients never send totals                                                            | Planned (Phase 4)                    |
| R-06 | High     | Sign-out leaves progress in localStorage; next user on a shared device inherits and merges it                                                     | `Account` sign-out                               | No client-held authoritative state; clear caches on sign-out                                                         | Planned (Phase 7/9)                  |

| R-08 | High     | Debrief trusts client-supplied `correct`/`bestAnswer`; student can make the AI endorse a wrong answer                                             | `debrief.server.ts`                              | Debrief built only from server-recorded attempt                                                                      | Planned (Phase 5)                    |
| R-09 | High     | Prompt injection via reasoning text; several fields unbounded                                                                                     | `debrief.server.ts`                              | Length caps, reasoning delimited as untrusted data, system prompt guardrails, structured output validated by zod     | Planned (Phase 5)                    |

## B. Clinical safety risks

| ID   | Severity | Risk                                                                                                                                             | Mitigation                                                                                                                                                                                                                             |
| ---- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-20 | High     | No mission has references or clinician approval; with D4 **nothing is playable until approvals exist** → launch blocked on reviewer availability | Recruit ≥ 2 reviewers early (Phase 6 start); reviewer workspace before web game UI completion                                                                                                                                          |
| R-21 | High     | AI debrief may state incorrect or invented guidelines                                                                                            | Prompt forbids citations other than the mission's approved references; low temperature; structured output; "education only" disclaimer; feedback "report a problem" flag; periodic clinician sampling of debriefs (Phase 5 acceptance) |
| R-22 | Medium   | Content written by non-clinician (stated in history) may contain errors                                                                          | All content passes clinician review before publication (D4); no AI-generated clinical content is ever auto-published                                                                                                                   |
| R-23 | Medium   | Guidelines differ by country (e.g. national malaria protocols)                                                                                   | `MissionVersion` carries country + reference set; reviewers confirm country applicability                                                                                                                                              |
| R-24 | Medium   | Regulatory classification — the platform must not be perceived as clinical decision support                                                      | Persistent education-only disclaimers, terms of use, no patient data entry                                                                                                                                                             |

## Product decisions needed (owner sign-off)

| Q   | Decision                            | Recommendation                                                                                                                                                        |
| --- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1  | Clinical Challenge rewards          | Practice mode: any **published** mission, no locks, **no HP/funding**; results recorded for learning stats                                                            |
| Q2  | When is a mission "done"?           | Done only when passed; the first pass awards the full score whenever it happens, so failing first costs nothing (replay rewards per Q8)                               |
| Q3  | Mobile offline play                 | Content browsing and resumable attempts cached; answering requires connectivity (keys stay server-side)                                                               |
| Q4  | Debrief references                  | Only cite references attached to the approved mission version; otherwise speak generally ("national guidelines")                                                      |
| Q5  | Pass rule                           | Keep ≥ 50 %, **plus** clinicians may mark choices as _critical errors_ that fail the case regardless of score                                                         |
| Q6  | Hero image                          | Confirm origin/licence or commission a replacement                                                                                                                    |
| Q7  | Infrastructure-as-code              | AWS CDK in TypeScript (same language as the stack)                                                                                                                    |
| Q8  | Economy balance                     | Replays award 30 % HP of improvement only and no funding; tier/country thresholds stored in DB and re-tuned as content grows (currently unreachable without grinding) |
| Q9  | Hosting region / data residency     | AWS `af-south-1` (Cape Town) + Atlas in the same region                                                                                                               |
| Q10 | Accessibility colour adjustment     | Approve slightly darker terracotta and green to meet WCAG AA                                                                                                          |
| Q11 | Currency symbol ₵ for all countries | Neutral in-game "Health Credits" icon; country currency only as flavour text                                                                                          |
| Q12 | Show scenario on every step         | Yes — collapsible scenario on steps ≥ 2                                                                                                                               |
